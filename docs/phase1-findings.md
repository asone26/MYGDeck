## 발견하고 고친 문제

1. **ConPTY 커서 위치 질문**: Windows 가상 터미널은 시작할 때 커서 위치를 묻고, 응답이 올 때까지 출력을 멈춘다. 앱에서는 xterm.js가 자동으로 답한다. 테스트는 직접 답하도록 수정.
2. **부모 Claude 세션 변수 상속**: 덱을 Claude Code 세션 안에서 띄우면 카드의 Claude가 하위 세션으로 동작해 대화 기록 저장이 꺼졌다. 세션 전용 변수만 제거 (`pty.rs` `INHERITED_SESSION_VARS`).
3. **`tauri dev` 인자 섞임**: `--color always`의 `always`가 프로젝트로 열림 → 존재하는 폴더만 프로젝트로 인정.
4. **합성 키 입력**: SendKeys·원격 도구는 `KeyboardEvent.code`가 비어 단축키가 안 먹음 → `e.key`로 대체 판단 (한글 입력 중에는 `code` 우선).
5. **카드 색 겹침**: 이름 해시만으로는 비슷한 색이 나옴 → 열린 카드끼리는 겹치지 않게 배정.
6. **화면 새로고침 시 CLI 고아 프로세스**: 화면 시작 시 이전 세션 정리 (`pty_reset`).

## 성능 실측 (release 빌드, 에이전트 프로세스 제외)

| 지표 | 목표 (master.md 2.2) | 실측 | 판정 |
|---|---|---|---|
| 실행 파일 크기 | ≤ 15MB | 3.75MB | ✅ |
| 창 표시 시간 | < 0.5초 | 0.14초 | ✅ |
| 덱 메모리 (프로젝트 0개) | ≤ 100MB | 163MB (private) | ❌ WebView2 기본 사용량 |
| 덱 메모리 (프로젝트 3개) | ≤ 150MB | 226MB (private) | ❌ |

- 빈 창(WebView2 프로세스 6개 포함)만으로 163MB. 첫 터미널(WebGL 렌더러)에서 약 60MB 늘고, 이후 프로젝트당 증가는 작다.
- 줄일 수 있는 여지: WebGL 대신 DOM 렌더러(GPU 메모리 절약, 대신 대량 출력 시 느림). 측정 후 판단.

## 사용 중 확인한 것

- 주간 사용 한도: 테스트 중 Claude Code가 "주간 한도 80% 사용"을 표시. 이후 테스트는 Claude에 지시를 보내지 않고 화면 동작만 확인.
