# 원격 서버에서 에이전트 돌리기

서버에서 도는 에이전트를 카드 하나로 띄우고, 노트북을 껐다 켜거나 네트워크가 끊겨도 같은 대화로 돌아오는 설정이다. 덱의 세션 데몬은 이 PC 안의 세션만 지키므로, 서버 쪽 세션은 서버의 tmux가 지킨다.

## 설정

`mygdeck.json`에 `command`로 ssh 명령을 적는다.

```json
{
  "projects": [
    {
      "path": "C:/work/api",
      "command": "ssh -t myserver \"tmux new -A -s api 'cd ~/api && claude'\""
    }
  ]
}
```

- `tmux new -A -s api`: `api` 세션이 있으면 붙고, 없으면 만든다. 그래서 끊긴 뒤 카드의 `↻ 다시 시작`을 누르면 서버에서 계속 돌던 에이전트 화면으로 돌아온다.
- `path`는 이 PC의 폴더다. 파일 탐색기·코드 뷰어·변경 배지가 이 폴더를 읽는다. 서버 코드를 보려면 같은 저장소를 받아 둔 폴더나 네트워크 드라이브(SSHFS 등)를 지정한다.
- 서버에 접속할 때 비밀번호를 묻지 않도록 ssh 키를 등록해 둔다. 카드 안에서 비밀번호를 입력할 수도 있지만 매번 해야 한다.

## 무엇이 유지되는가

| 상황 | 결과 |
|---|---|
| 덱 창을 닫았다 연다 | 로컬 데몬이 ssh 연결을 유지한다. 창을 열면 그대로 이어진다 |
| 노트북 재부팅, 네트워크 끊김 | ssh는 끊기고 서버의 tmux 세션은 남는다. `↻ 다시 시작`으로 다시 붙는다 |
| 서버 재부팅 | 서버 세션도 끝난다. 다시 시작하면 새 대화가 열린다 |

## 제약

- 원격 카드는 GUI 화면 없이 원본 CLI로 보인다. hooks 프로그램이 이 PC에 있어 서버의 에이전트가 실행할 수 없기 때문이다. 상태는 출력이 멈춘 시간으로 추정한다.
- `mygdeck-cli send`는 원격 카드에도 동작한다. 로컬 데몬이 ssh 세션에 입력을 넣는다.
- tmux 대신 서버용 에이전트 멀티플렉서(herdr 등)를 써도 구조는 같다. 붙는 명령만 그 도구의 것으로 바꾼다.
